# Scenario Data

TrafficGym does not author or synthesize any real-world network or demand
data. Every real-world scenario is consumed as-is from public MATSim
open-scenario repositories; the only synthetic data generated by this
project is the `grid_world` family of controlled scaling benchmarks.

To keep this repository small, only small scenarios are committed directly.
Larger real-world scenarios are fetched on demand with
[`scripts/fetch_scenario_data.py`](scripts/fetch_scenario_data.py).

## Shipped out of the box

| Scenario | Source | Notes |
|---|---|---|
| `sioux_falls` | [matsim-eth/matsim-tutorial-ctu-2020](https://github.com/matsim-eth/matsim-tutorial-ctu-2020) | Classic LeBlanc/Morlok/Pierskalla 282-node network, shipped with its own OD matrix at 400% of the tutorial's base demand, used unmodified. |
| `grid_world/{3x3, 3x3_uni, 8x8}` | generated locally | Synthetic Manhattan grid lattices; regenerate any size with `generate_grid_scenario.py` / `generate_grid_scenario_uniqueOD.py` / `generate_random_grid_scenario.py`. |
| `braess`, `equil`, `equil_biased`, `toy_corridor`, `toy_corridor_2`, `saint_arnoult`, `ortuzar_willumsen` | generated locally | Small synthetic/textbook toy networks used for unit tests and equilibrium sanity checks. |
| `ingolstadt` | MATSim scenario ecosystem (kept locally, ~33 MB) | Used for the DNL-vs-MATSim fidelity appendix. Its shipped population has only origin/destination link pairs (no contiguous routes); `scripts/generate_ingolstadt_fixed_routes.py` regenerates free-flow-shortest-path routes as ground truth. |

## Fetched on demand

```bash
python scripts/fetch_scenario_data.py --list                    # see everything available
python scripts/fetch_scenario_data.py --scenario berlin         # one scenario
python scripts/fetch_scenario_data.py --all                     # everything (tens of GB)
```

The download URLs point at the VSP TU-Berlin public SVN server, which is
where these repositories actually publish their (large) input files; the
GitHub repos themselves only hold code and small config. In every source
repository, MATSim's own program code is GPL-2.0 licensed, but TrafficGym
never redistributes or depends on any of that code — only the network and
population XML input files (CC-BY 4.0, except Kelheim as noted above) are
consumed, reformatted into CSR tensors at load time. No link geometry,
capacity, or trip is synthesized or altered.

Upstream filenames occasionally differ slightly from older local naming
conventions you may see referenced in code comments (e.g. no `-car-only` or
`-routed` suffixes exist upstream — `tamarl/envs/scenario_loader.py` already
filters to `mode="car"` links/legs itself at parse time, so raw downloaded
files load directly for RL training). The stricter DNL-vs-MATSim fidelity
validation (`tamarl/validation/`, `scripts/validate_against_matsim.py`)
replays literal fixed routes and may require an extra routing/repair pass;
see `tamarl/data/scenarios/berlin/clean_create_path.py` and
`scripts/generate_ingolstadt_fixed_routes.py` for the utilities used to
prepare such populations.

Fetching the full library takes tens of GB and, for Los Angeles/Berlin at
higher population fractions, non-trivial RAM (see
[REPRODUCIBILITY.md](REPRODUCIBILITY.md) for the hardware used to produce
the paper's results).
